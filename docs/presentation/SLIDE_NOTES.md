## Slide 4: SAFETY (Layer 1: Static Rules)

### Slide Header & Content in Deck 11
```
SAFETY
Bounded agency: the code-level guarantee
The model can suggest. The safety engine decides what is allowed.
LAYER 1 — STATIC RULES
```

### Presenter Lead: **Lucas Whitaker** (1:05)

### Spoken Speaker Script (Verbatim Rehearsal):
> “In generative AI systems, prompt engineering is guidance—it is not a security boundary. If an LLM hallucinates a destructive command or encounters prompt injection, relying on system instructions alone will fail.
>
> GitPet implements a **2-Layer Safety Policy Engine** in code.
>
> **Layer 1 enforces Static Invariants** regardless of repository state:
> - **Zero Un-Leased Force-Pushes:** `git push --force` or `-f` is hard-rejected; the engine automatically suggests `--force-with-lease`.
> - **Zero Destructive Resets:** `git reset --hard` is blocked; the engine suggests `--keep` or stashing.
> - **Zero Permanent Deletions:** `git clean -fdx`, `git branch -D`, and `git stash drop` are forbidden.
> - **Zero Shell Injection:** Metacharacters like `;`, `|`, `&`, `$()`, and backticks are rejected. Commands are tokenized into pure `argv` arrays and executed via `child_process.execFile` without shell pass-through.
> - **Binary Whitelist:** Only the `git` executable is permitted—commands like `sudo`, `rm`, `curl`, or `sh` are dropped at the gateway router.”

### Presenter Lead: **Lucas Whitaker** (1:05)

### Spoken Speaker Script (Verbatim Rehearsal):
> “That brings us to **Layer 2: Contextual Safety Lints**.
>
> Layer 2 compares the proposed command against the live working tree, staging index, and Git directory state before approving execution.
>
> For example:
> 1. **Untracked File Stash Protection (`stash-misses-untracked`):** If a developer has untracked files and the AI suggests a bare `git stash`, Git would silently leave those files behind, causing subsequent branch pulls to overwrite or conflict with them. Layer 2 catches this and automatically upgrades the command to `git stash push -u`.
> 2. **Diverged Pull Prevention (`ff-only-on-diverged`):** If a branch is both ahead and behind, `git pull --ff-only` will fail. Layer 2 detects divergence and recommends `git pull --rebase`.
> 3. **Operation-in-Progress Guard (`operation-in-progress`):** If a rebase or merge is paused, commands are strictly restricted to `--continue`, `--skip`, `--abort`, or read-only queries.
>
> Furthermore, all write execution is disabled by default and requires `GITPET_ALLOW_WRITES=true`. When executed, GitPet records `headBefore` and `headAfter` commit hashes, ensuring 1-click rollback guarantees.”

## Complete Rehearsal Q&A Playbook for Judges

### Q1: How does GitPet prevent prompt injection or jailbreak attacks from executing destructive shell commands?
* **Answer:** *"GitPet never treats LLM output as executable code. All suggested commands pass through our 2-layer safety policy (`safety.ts`). Layer 1 statically blocks dangerous patterns like `git push --force`, `git reset --hard`, `git clean -fdx`, and shell metacharacters. Layer 2 verifies working tree state. Commands are tokenized into argv arrays and executed via `child_process.execFile`—never a shell. Even if an LLM is completely compromised, it cannot execute destructive commands."*

### Q2: What happens if the Gemini API key is missing or quota is exhausted (HTTP 429)?
* **Answer:** *"GitPet is built with 100% offline resilience. If `GEMINI_API_KEY` is missing or returns 429 quota exhaustion, our deterministic rule engine (`generateRuleBasedAction`) immediately activates. It evaluates the exact same repository state, computes 7-factor risk scores, and generates verified, safe Git actions with evidence citations and reversal commands."*

### Q3: How does the DAG visualizer scale with large commit histories?
* **Answer:** *"The DAG normalizer (`gitDagNormalizer.ts`) uses topological sorting and lane assignment algorithms that bound the render window to active branch lineages (default: 12–25 recent commits). It detects merge bases, collapses linear commit runs when needed, and renders smooth cubic bezier splines with zero layout thrashing."*

### Q4: How is human-in-the-loop safety guaranteed for write operations?
* **Answer:** *"All write execution is disabled by default and requires `GITPET_ALLOW_WRITES=true`. When a developer clicks 'Confirm & Execute', the action opens a preview diff modal showing affected files, blast radius, and reversal commands. The command is re-evaluated against the safety engine at execution time, preventing any client-side tampering."*
